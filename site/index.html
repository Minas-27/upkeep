upkeep v0.1.0 a Flutter project health report

The problem, measured by Google

44% of Flutter developer frustration is version guesswork.

That figure is not a pitch. It is Google's own Q2 2026 Flutter survey, which found that platform and ecosystem maturity drives 44% of developer dissatisfaction, and named the cause outright: hours lost juggling Flutter, Dart, Gradle, Kotlin and JVM versions. Meanwhile packages die quietly, and nothing tells you.

44% of developer dissatisfaction traced to ecosystem and version-matrix problems
18% say the critical packages they need do not exist yet
0 existing tools that flag a dying dependency and name its replacement

Source: Flutter Q2 2026 user survey, flutter.dev · the third figure is what a search of the pub ecosystem turns up, where the standing advice is to check by hand.

The tool

One command. Every verdict shows its reasons.

upkeep scan reads the project you are standing in and reports what is actually wrong with it.

What it checks

Your dependencies

Scored against pub.dev's own data, not opinion.

  • Release recency and pub points
  • Dart 3 and WASM readiness
  • SDK constraints that block an upgrade
  • The official discontinued flag — and the replacement the publisher named

Your Android build matrix

Validated against Google's published requirements for AGP 8.0 through 9.4.

  • Gradle wrapper against the AGP in use
  • JDK against the AGP minimum
  • compileSdk against the documented ceiling
  • The exact command that fixes each failure
DISCONTINUED

The publisher said stop. Popularity does not override it.

INCOMPATIBLE

The package's own ceiling excludes your Dart. No release is coming.

AT RISK

More than one warning sign, each one named.

SDK BLOCKED

Your Flutter is behind. Grouped into one line, never fails your build.

HEALTHY

Checked, and nothing to say.

The rules it holds itself to

A tool that judges your dependencies has one asset, and it is trust.

Each of these exists because an earlier version of the engine got a verdict wrong.

Missing data is never evidence

When pub.dev cannot be reached, the verdict is unknown, not dead. Requests retry, and a dropped response is never reported as a missing package. An early build accused a perfectly maintained package of neglect on the strength of one truncated HTTP response.

Popularity never overrides a discontinued flag

pedantic is discontinued, scores a perfect 160 of 160, and is still downloaded hundreds of thousands of times a month. A rule that trusted downloads called it healthy. The publisher's word wins.

The resolver gets the last word

Packages like isar and hive cap themselves below Dart 3 yet still resolve, because pub relaxes that bound for null-safe packages. Where pub.dev's compatibility tag contradicts the arithmetic, the tag wins — because that is what actually happens when you run pub get.

Stable is not abandoned

A small, finished, widely used package that has not needed a release in two years is not dying. It is done.

No guessing

Where Google does not publish a number, upkeep says it cannot check rather than inventing one. Where a value had to be inferred, it softens the verdict instead of hardening it.

Using it

Install, scan, or drop it into CI.

dart pub global activate upkeep
upkeep scan
- run: dart pub global activate upkeep
- run: upkeep scan
Exit codeMeaning
0Clean
1Blocking: a discontinued, incompatible or dead dependency, or an Android matrix that does not build
2The scan could not run

Responses cache for 24 hours, so repeat scans do no network work. Add --fail-on-at-risk to treat warnings as failures.

Where it is going

Diagnosis first. Treatment once the diagnosis is trusted.

0.1Scan, verdicts, Android matrix, CI exit codes. Built and tested.
0.2JSON output, upkeep explain, curated replacements for packages that died without ever being marked discontinued.
0.3upkeep fix — guided and reversible, and it refuses to run on a dirty git tree.
0.4A GitHub Action, because CI is where a tool becomes a habit.
1.0A GitHub App that opens the upgrade pull request for you.

The command line tool is free and MIT licensed, and stays that way. The compounding asset is the knowledge base behind it — the compatibility matrix, the replacement map, the known-bad combinations — which can only be built by paying attention every week for years.
